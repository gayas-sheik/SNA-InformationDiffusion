# Information Diffusion in Social Networks

---

# 1. First: What is this project about?

Imagine this situation:

You post something on a social network.

Someone sees it.

They share it.

Another person sees the shared post and shares it again.

Someone from another community sees it and shares it.

Eventually, the same piece of information may move:

**Person → Person → Person → Community → Another Community → Another Platform**

That entire process is called **information diffusion**.

Our project asks:

> **How does information spread through a social network, and what factors determine how far, how fast, and through whom it spreads?**

The project studies this using **Social Network Analysis (SNA)**.

Our exact problem statement is:

> **"To analyze how information spreads through social networks and identify how user influence, network structure, communities, and time affect the propagation of information."** SNA-FinalReport

---

# 2. What is Social Network Analysis?

Before understanding our project, you need to understand SNA.

Social Network Analysis is a way of studying **relationships between entities** using a network.

For example:

```text
Alice → Bob
Bob → Charlie
Charlie → David
Alice → David
```

We can represent this as a graph:

```text
Alice
 ↓   ↘
Bob   David
 ↓
Charlie
 ↓
David
```

There are two fundamental things:

### Node

A **node** represents an entity.

In our project:

> **A node = a user**

So:

```text
U00001
U00002
U00003
...
```

are users.

### Edge

An **edge** represents a relationship or interaction between two nodes.

For example:

```text
U00001 → U00042
```

means user U00001 interacted with U00042.

Therefore:

> **Our social network is a graph where users are nodes and user-to-user interactions are directed edges.**

---

# 3. Why are the edges directed?

This is very important.

Suppose:

```text
Alice → Bob
```

Alice interacted with Bob.

That doesn't automatically mean:

```text
Bob → Alice
```

The direction matters.

For example, if Alice shares Bob's content:

```text
Alice → Bob
```

is different from:

```text
Bob → Alice
```

Therefore, our network is a:

> **Directed interaction network.**

# 10. What does "sparse" mean?

A network is sparse when only a small fraction of all possible connections actually exist.

Imagine 10,000 people.

There could theoretically be an enormous number of possible connections.

But our network has only:

> 48,463 unique interaction edges.

So most possible user-to-user connections don't exist.

That's why we describe it as sparse.

---

# 11. What is network density?

Density tells us:

> How many of the possible connections actually exist?

A density close to zero means the network is very sparse.

Our density:

> **0.000485**

So only a very small fraction of possible directed connections occur.

# 13. Phase 2 — User Influence

Now we ask:

> Are some users structurally more important than others?

To answer this, we use **centrality measures**.

Centrality basically means:

> "How important or strategically positioned is a node in a network?"

We used five centrality measures:

1. Degree centrality
2. PageRank
3. Betweenness centrality
4. Closeness centrality
5. Eigenvector centrality

---

# 14. Degree centrality

The simplest one.

It asks:

> How many connections does a user have?

For a directed network we can distinguish:

### In-degree

How many users interact **toward** this user?

```text
A ──→
B ──→ C
D ──→
```

C has:

```text
In-degree = 3
```

### Out-degree

How many users does this user interact toward?

So degree gives us a basic measurement of network activity/connectedness.

---

# 15. PageRank

PageRank is more sophisticated.

It doesn't simply ask:

> "How many connections does this user have?"

It also considers:

> "Who is connecting to this user?"

A connection from an important user can contribute more importance than a connection from an insignificant user.

So PageRank helps identify users that are structurally important in the network.

In our analysis:

> **Influence ↔ PageRank correlation = 0.7014**

This is one of our most important results.

---

# 16. What does correlation 0.7014 mean?

Correlation measures the strength of association between two variables.

A value near:

```text
0 → little linear association
1 → strong positive association
-1 → strong negative association
```

Our value:

> **0.7014**

indicates a fairly strong positive association.

So:

> Users with higher influence scores tend to have higher PageRank values in our synthetic network.

But **DO NOT SAY**:

> "High PageRank causes high influence."

That would be wrong.

Our report explicitly says this is an **association, not causation**. SNA-FinalReport

---

# 17. Other centrality measures

### Betweenness centrality

Asks:

> How often does a user lie on paths connecting other users?

This can identify bridge-like positions.

---

### Closeness centrality

Asks:

> How close is a user to the rest of the network?

A user with high closeness can theoretically reach other nodes through relatively short paths.

---

### Eigenvector centrality

Asks:

> Is a user connected to other important users?

So:

```text
Important user
      ↓
Important user
      ↓
You
```

can increase your structural importance.

# 21. What is cascade size?

Cascade size means:

> How many propagation events/interactions are contained in the cascade.

If:

```text
A → B → C → D
```

then the cascade has several propagation events.

A larger cascade means the information propagated through more interactions.

---

# 22. What is cascade depth?

Depth measures how far the information travels along the cascade path.

For example:

```text
A
 ↓
B
 ↓
C
 ↓
D
```

has a deeper chain than:

```text
A
 ↓
B
```

---

# 23. VERY IMPORTANT limitation: our cascades are chain-like

This is something you absolutely must understand.

In our dataset:

> **cascade size and cascade depth are exactly equal.**

Why?

Because our generated cascades are predominantly **linear chains rather than branching trees**.

Real social-media diffusion can look like:

```text
             → B
            ↗
A → 
            ↘
             → C
                 ↘
                  D
```

One person can influence several people.

Our synthetic cascades are much closer to:

```text
A → B → C → D → E → F
```

Therefore:

> We can analyze cascade size, depth, duration and cross-boundary movement, but we should not claim that we performed rich branching-topology analysis.

This limitation is explicitly documented in the report. SNA-FinalReport

# 37. Does an influential user guarantee a large cascade?

**No.**

This is a very important distinction.

Our analysis found that influence is associated with structural importance.

But the relationship between root-user influence and cascade size was very weak.

Therefore we cannot say:

> "The most influential user always creates the largest cascade."

In fact, one of the largest cascades had a **Regular** root user.

That is useful because it shows:

> User influence alone does not explain the entire diffusion process.

Network structure, connections, platform movement, community movement and temporal factors all matter.

And again:

> **Association does not equal causation.**

# 40. Limitations

This is a section you absolutely need to know.

## Limitation 1 — Synthetic dataset

The data is simulated.

Therefore:

> Results cannot automatically be generalized to real social networks.

---

## Limitation 2 — Chain-like cascades

Our cascades are predominantly linear.

Therefore:

> Rich branching cascade topology isn't fully represented.

---

## Limitation 3 — Controlled platform distribution

The platforms were generated in a controlled way.

Therefore:

> We cannot interpret platform frequencies as real-world platform behavior.

---

## Limitation 4 — Controlled community distribution

The communities were also controlled.

Therefore:

> Community-level differences should not be interpreted as actual social-community behavior.

---

## Limitation 5 — Temporal peaks are synthetic

The:

```text
23:00 peak
Tuesday peak
```

are simulation outputs.

We shouldn't invent explanations for them.

---

## Limitation 6 — No causal claims

If we observe:

```text
Influence ↑
PageRank ↑
```

we can say:

> They are positively associated.

We cannot say:

> Influence causes PageRank.

This distinction is fundamental.
